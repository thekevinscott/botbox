Fixed: **BREAKING** `adocker`'s `Image.run` returns only once the container is running, so an `exec`, `remove` or `wait` right after it acts on that container. Before, it returned once the `docker run` client was spawned: an `exec` could fail with "No such container", and a `remove` could find nothing to remove, leaving `wait` stuck on a container created a moment later. It now runs `docker create`, then an attached `docker start --attach`, and waits for the daemon's start event. A container Docker can't create raises `DockerException` from `Image.run`, with `return_code` 1 instead of the client's 125; botbox's `run()` and `session()` raise it the same way, `session()` on entering. `Container.docker_command` is the `docker start` command. See [the migration](../migrations.d/2026-10-26-python-image-run-running.md).
