# botbox: pi 1.4, and a pi session turn ends at `agent_settled`

## Summary

The pi image runs pi 1.4.0. A `PiAgent` session turn's last event is `agent_settled`, not `agent_end`, and `agent_end` can appear more than once in a turn. `message_update` and `tool_execution_update` are back in session events and `RunResult.stdout`.

## Required changes

Code that looked for `agent_end` as a turn's last event looks for `agent_settled`. Code that reads `message_update` reads `assistantMessageEvent.delta`: the cumulative `message` and `assistantMessageEvent.partial` fields are gone in pi 1.4, and `message_end` still carries the final message.

## Deprecations removed

None.

## Behavior changes without code changes

With no model selected, pi chooses its own default without a `--provider` flag. Streaming updates now appear in session events and `RunResult.stdout`. The image disables pi's startup network checks with `PI_OFFLINE=1`.

## Verification

After building the pi image, run `docker run --rm botbox-pi:latest pi --version` and expect `1.4.0`. In a pi session, expect `agent_settled` as each turn's final event and `message_update` events with `assistantMessageEvent` deltas.
